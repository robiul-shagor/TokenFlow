# Threat model (initial)

**Scope:** a portfolio prototype that runs on local Anvil (`31337`) or a public testnet (Sepolia, Base Sepolia; see
[deployment.md](deployment.md)), with test tokens that have no monetary value. Mainnets are refused. It is not
audited and not production software. This document lists the assumptions, the trust boundaries and the risks we
know about.

## Assets

- Correct vesting accounting: released ≤ vested ≤ allocated, and the registry stays solvent.
- Integrity of the indexed read model and of reconciliation reports, which operators may act on.
- Developer machines: no real keys or secrets should ever be needed or committed.

## Trust boundaries

| Boundary | Trust | Controls |
|---|---|---|
| Browser → contract | Untrusted caller | `AccessControl` on `createSchedule`; only the beneficiary can `release`; all input validated on-chain. Hiding a button is not access control. |
| Browser → API | Untrusted input | Size limits (1 MB CSV), strict parsing, chain and contract checked against the configured deployment, generic error messages. Public networks: per-IP rate limits, and saving a report needs a fresh, non-replayed signature from a `SCHEDULE_MANAGER_ROLE` holder (verified on-chain) |
| RPC → indexer | Trusted node / provider | Chain ID asserted at startup; indexes only `latest − confirmations` (3 on testnets); block-hash check on the cursor stops on deeper reorgs or chain resets |
| Server → browser config | Public | Only `PUBLIC_RPC_URL` or the chain's public endpoint is sent; `RPC_URL` (may hold an API key) stays server-side, and startup rejects `PUBLIC_RPC_URL == RPC_URL` |
| CSV file | Untrusted | Validated row by row; duplicates surfaced; exact integer conversion; formula-injection-safe export |
| Deployment manifest | Generated by the deploy script | `chainId` must equal the `NETWORK` profile's chain, mainnet IDs are always refused, and addresses must be valid, or the app refuses to start (fail closed). The deploy script itself only runs on 31337 / 11155111 / 84532 |

## STRIDE summary

| Threat | Example | Mitigation | Residual risk |
|---|---|---|---|
| **S**poofing | Someone claims another person's allocation | `msg.sender == beneficiary` check; invariant test `invariant_noForeignRelease` | None known |
| **T**ampering | Fee-on-transfer token under-funds a schedule | Balance-delta check reverts `UnsupportedToken` | Rebasing tokens can still change balances after funding. Only the bundled mock token is supported. |
| **T**ampering | Re-entrancy via a malicious token | `nonReentrant` + checks-effects-interactions | Not audited |
| **T**ampering | Replayed or duplicated events inflate `released` | Unique event key; projection only on insert; one transaction per batch | — |
| **T**ampering | A reorg removes events already indexed | Confirmation depth; block-hash cursor check halts on deeper reorgs | A reorg deeper than the depth needs a manual `--reset` |
| **R**epudiation | "The report said X" | Reports persist the chain, contract, indexed block, head block and stale flag; on public networks only role-holders can save them | The signer's address is verified but not yet stored with the report |
| **I**nformation disclosure | Keys leak through the bundle, logs or screenshots | No plaintext keys: unlocked Anvil accounts locally, encrypted keystore or Ledger for testnet deploys; `.env*` is git-ignored; gitleaks runs in CI; `/api/health` names missing settings but never echoes values | Someone could still use a real wallet on the testnet demo. The banner and docs warn against it. |
| **D**enial of service | Huge CSV or request floods | 1 MB / 10,000-row limits; per-IP rate limits on public networks | Limits are in-memory (one instance); trusts the proxy's `X-Forwarded-For` |
| **E**levation of privilege | Non-manager creates schedules | `SCHEDULE_MANAGER_ROLE`; tested; UI warns, but the contract enforces | `DEFAULT_ADMIN_ROLE` is a single EOA, with no multisig or timelock |

## Out of scope / known limitations

- Mainnet. No mainnet profile exists, by design ([ADR 0006](decisions/0006-network-profiles.md)).
- Locally, the API has no authentication (single operator); set `REQUIRE_REPORT_SIGNATURE=1` to require signatures
  there too.
- No strict Content-Security-Policy yet (baseline security headers only).
- Independent security review. Slither findings are reviewed in [testing.md](testing.md).
